# 会话中心区重构设计

## 目标

将会话页从功能堆叠的聊天界面调整为数字员工的核心工作台。使用者在进入页面后，应能立即判断当前处置事件、执行状态和下一步待办；对话始终拥有最大的连续阅读区域。

## 已确认方向

- 布局采用“对话优先，上下文按需抽屉”。
- 不使用固定三栏，也不保留持续占用宽度的右侧信息栏。
- 顶部优先呈现当前事件与处置状态；智能体、模型、模式为次级控件。
- 会话列表按需从左侧抽屉打开；上下文、证据、任务、审批和审计按需从右侧抽屉打开。

## 页面结构

### 1. 事件工作头部

头部使用一条紧凑的工作条，包含：

- 事件标题与会话名称；
- P 级别、处置状态、风险等级和人工接管状态；
- 当前责任人、待审批或待执行的下一步；
- 会话列表、上下文抽屉、更多操作三个入口。

“研判 / 受控执行”保留为轻量分段控件。智能体与模型不再占用标题行，而在输入区上下文条中显示和调整。

### 2. 连续对话区

消息区为页面唯一的主面板，最大阅读宽度约为 920px，并在宽屏中居中。消息按行动阶段组织：

- 用户指令；
- 数字员工结论；
- 可折叠的推理、证据、工具调用；
- 审批、任务和执行结果行动卡。

行动卡只显示当前状态和一个明确动作。详情不在消息内展开成长表，而由“查看证据”“打开任务”“查看审批”等入口打开右侧抽屉。

### 3. 输入工作台

输入区固定于主面板底部，保持输入优先。顶部只显示当前会话、执行模式、附件和工具上下文；编辑器下方放置附件、语音、工具、模型、令牌用量和发送。

输入区不再承载事件概要、待办列表或重复的运行状态。

### 4. 按需抽屉

右侧抽屉默认关闭，宽度为 420–480px，并有以下标签：

- 概览：当前状态、责任人、关联资产和下一步；
- 证据：引用、检索来源、监控与工具输出；
- 任务：会话创建或关联的任务及执行状态；
- 审批：签名人、审批决策和风险说明；
- 审计：按时间排列的可追溯事件。

左侧会话抽屉通过顶部“会话”入口打开，保留搜索、分组、置顶与新建能力。任一时刻只允许一个抽屉展开。

## 数据与交互

- 现有 `useChat` 继续作为会话、流式消息与审批状态的唯一前端状态来源。
- 现有共享 Mock API 继续负责任务、审计和渠道事件写入；抽屉读取同一 API 数据并按需刷新。
- 最终审批触发的创建任务和受控执行会在消息行动卡、右侧任务标签和任务页面中一致呈现。
- `Esc` 关闭当前抽屉；打开一个抽屉时自动关闭另一个；移动端抽屉全宽显示。

## 错误与空状态

- 空会话显示面向业务动作的起始提示与快捷指令，不显示装饰性空卡片。
- 流式失败、权限拒绝和审批过期均留在对应消息行动卡内，并提供重试或查看原因入口。
- 抽屉 API 加载失败时显示局部错误与重试，不影响对话输入。

## 验收标准

1. 默认打开会话时，不存在固定左右栏；对话区为唯一主面板。
2. 顶部可在一行内识别事件、风险、处置状态及下一待办。
3. 会话列表和运行上下文均可从顶部入口按需打开并关闭。
4. 点击消息中的证据、任务或审批入口，会打开右侧对应标签，而非挤压聊天区域。
5. 审批后的任务创建与执行状态，在会话、抽屉、任务页、渠道流和审计流中保持一致。
6. 现有键盘输入、流式停止、引用查看、任务回写、人工接管和调试能力不回归。
