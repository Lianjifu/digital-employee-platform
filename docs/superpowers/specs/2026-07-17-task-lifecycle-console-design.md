# 企业数字员工任务生命周期控制台设计

## 目标

将任务页从包含大量静态 KPI、筛选器和局部交互的任务列表，升级为企业数字员工的任务生命周期控制台。用户应在首屏识别需要其介入的事项，并能在同一任务上下文中完成分派、审批、接管、重试、协作和审计追溯。

任务页覆盖以下闭环：

```text
会话 / 告警 / 工作流触发
  -> 创建与分派
  -> 数字员工执行
  -> 审批、人工接管或异常处置
  -> 完成、复盘与审计归档
```

## 已确认原则

- 任务页采用单一主面板，不使用固定三栏。
- 点击任务始终按需打开右侧生命周期详情抽屉。
- 品牌色为靛蓝 `#4f46e5`；红色只表达失败、超时和告警，不作为品牌强调色。
- 优先展示待处置事项和风险，而非统计装饰。
- 任务、审批、执行和审计必须通过统一 Mock 领域状态维护，不能只留在页面本地状态。

## 页面信息架构

```text
任务控制台
├─ 行动摘要：待处理 / SLA 风险 / 待审批或待接管
├─ 工作工具栏：搜索、状态、负责人、风险、更多筛选、视图、新建任务
├─ 任务主面板：生命周期看板 / 运营列表 / 时间线
└─ 右侧生命周期详情抽屉：概览、执行、审批与风险、资产与依赖、审计与协作
```

### 行动摘要

顶部只保留以下三个可点击摘要卡，点击后应用相应的筛选预设：

| 摘要 | 定义 | 筛选结果 |
| --- | --- | --- |
| 待处理 | 当前用户需要确认、分派或处置的任务 | 待处理和等待人工动作 |
| SLA 风险 | 已超时或临近超时的未归档任务 | SLA 风险优先，按剩余时间排序 |
| 待审批 | 等待审批、双签或人工接管的任务 | 等待人工动作 |

移除非行动型的重复 KPI 和持续占用首屏的 SLA 风险地图。完成率、总量等运营指标可在后续报表或筛选结果摘要中展示。

### 工作工具栏

常驻控件为：

```text
[搜索任务、编号或资产] [状态] [负责人] [风险] [筛选]  [看板 | 列表 | 时间线] [新建任务]
```

“筛选”弹层承载优先级、数字员工、标签、来源、依赖、审批状态、创建时间和归档状态。已选条件显示为可单独清除的 Chip。批量操作只在选择一项或多项任务后出现。

## 主面板设计

### 生命周期看板

默认视图使用以下列，列顺序体现处置优先级而非简单进度：

```text
待处理 -> 执行中 -> 等待人工动作 -> 风险 / 异常 -> 已完成
```

“等待人工动作”包括审批、双签和人工接管；“风险 / 异常”包括执行失败、SLA 超时、依赖阻塞和策略拦截。归档任务不占用主看板列，通过筛选查看。

任务卡只展示处置所需的信息：优先级和 SLA、任务标题、当前阶段、责任人或数字员工、来源或关联对象、依赖或风险标记。卡片点击打开详情，不能以多个常驻按钮替代详情入口。

拖拽仅作为状态流转请求的入口。前端必须等待 API 校验成功后更新；审批未通过、依赖未完成、权限不足或状态不允许时，保留原位置并显示具体原因。

### 运营列表与时间线

列表适合检索和批量管理，列为：任务编号与标题、当前阶段、优先级、负责人、数字员工、SLA、最后更新和操作状态。行内只保留“打开详情”。

时间线按任务生命周期事件展示创建、状态变更、数字员工执行步骤、审批、接管、SLA 升级、完成和归档，支持按任务来源或风险等级筛选。

## 右侧生命周期详情抽屉

抽屉是唯一的深度任务操作入口。顶部显示任务名称、任务编号、优先级、当前阶段、SLA 和来源。

| 标签 | 内容 |
| --- | --- |
| 概览 | 目标、当前阶段、责任人、数字员工、SLA、来源和关联对象 |
| 执行 | 运行步骤、工具调用、执行输出、失败原因和重试记录 |
| 审批与风险 | 审批策略、签署人、拒绝原因、风险说明、接管和升级记录 |
| 资产与依赖 | CMDB 资产、关联告警、工作流、前置和后置任务 |
| 审计与协作 | 不可篡改式审计事件、评论、附件和导出记录 |

抽屉底部按任务状态只展示一个主操作：待处理时开始执行或分派；待审批时批准或驳回；待接管时人工接管；失败时重试；执行中时暂停；完成后确认归档。导出审计记录作为次级操作。归档、拒绝和强制接管等不可逆操作须要求确认和原因。

## 视觉规范

### 字体

- 页面标题：16px / 600。
- 区域标题：14px / 600。
- 任务标题：14–15px / 500–600。
- 表格与正文：13px / 400。
- 时间、标签和辅助信息：11–12px。
- 哈希、运行 ID 和技术标识：10–11px 等宽字体。

应移除大面积 9px 与 10px 常规文本，避免企业运营界面难以快速扫描。

### 颜色与组件

- 靛蓝仅用于主按钮、当前选中状态和关键链接。
- `#10b981` 表达成功或完成，`#f59e0b` 表达临期和待处理，`#ef4444` 表达超时、失败、阻塞和拒绝。
- 中性状态使用灰蓝，不以高饱和色表达普通进度。
- 筛选选中态使用浅靛蓝背景与靛蓝文字，不使用大面积实心填充。
- 任务卡使用白底、12px 圆角、细边框和轻阴影；悬停只轻微提升，不使用装饰性渐变。

## Mock API 与领域模型

### 目标

Mock API 需成为任务、会话、首页、审计和渠道通知的共同事实来源。页面可维护抽屉、筛选、视图和临时表单等 UI 状态，但不能维护独立任务事实状态。

### API 契约

```text
GET    /api/tasks
POST   /api/tasks
GET    /api/tasks/:id
PATCH  /api/tasks/:id
POST   /api/tasks/:id/transition
POST   /api/tasks/:id/approve
POST   /api/tasks/:id/takeover
POST   /api/tasks/:id/retry
POST   /api/tasks/:id/comments
POST   /api/tasks/:id/attachments
GET    /api/tasks/:id/timeline
POST   /api/tasks/batch
POST   /api/mock/reset
```

`GET /api/tasks` 支持状态、负责人、风险、来源、审批、标签、排序和分页参数。写接口返回更新后的任务及受影响的生命周期事件；前端据此刷新相关查询。

### 领域字段

每项任务至少具有：

```ts
{
  id, code, title, lifecycleStage, priority, assignee, agent,
  source, sla, execution, approval, risks, links,
  dependencies, auditEvents, version
}
```

- `source`：会话、告警、工作流或手工创建。
- `sla`：截止时间、剩余时间、风险等级和升级状态。
- `execution`：运行 ID、步骤、工具调用、错误和重试次数。
- `approval`：审批策略、签署人、结论、截止时间和拒绝理由。
- `links`：来源会话、告警、工作流、CMDB 资产与关联任务。
- `version`：用于模拟并发更新冲突。

### 状态规则

```text
待处理 -> 执行中
执行中 -> 等待人工动作 / 风险异常 / 已完成
等待人工动作 -> 执行中 / 待处理
风险异常 -> 执行中 / 等待人工动作 / 已归档
已完成 -> 已归档
```

状态流转由 API 校验；依赖未满足、审批未通过、无权限或操作版本过期时，API 返回可展示的业务错误，而不是前端产生假成功。

## Mock 场景与错误处理

必须提供以下可切换或可触发场景：P0 超时、双签待审批、执行失败、依赖阻塞、会话创建任务、工作流创建任务、无权限、慢响应、请求失败、并发冲突及批量部分失败。

延迟至少模拟 80ms、800ms 和 3s 三档，并支持返回权限、冲突、校验和服务错误。前端在加载时显示局部 Skeleton；提交中禁用重复提交；失败时显示可理解的原因与重试入口；批量操作逐项反馈成功和失败结果。

## 跨模块数据流

```text
用户操作
  -> Task Mutation API
  -> 统一 Mock 领域状态
  -> 任务查询刷新、首页摘要刷新、会话关联任务刷新、审计流刷新、渠道通知刷新
```

会话创建或执行任务后，任务页应更新既有任务及新增任务，不只合并新增任务。任务详情中的审计记录必须来自同一领域事件流，以保持设置页、会话上下文与任务详情一致。

## 分期与验收

### 第一阶段：Mock 生命周期闭环

补齐任务写接口、状态流转校验、领域事件和场景模拟；将任务页的创建、拖拽、批量、签发、评论、附件和归档迁移至 Mutation。

### 第二阶段：任务控制台重构

改造行动摘要、工具栏、生命周期看板、列表和时间线；统一字体、颜色、卡片、按钮和空状态。

### 第三阶段：详情与治理完善

重构详情抽屉，接入状态驱动主操作、审批、人工接管、执行重试、资产与依赖、统一审计和批量部分失败反馈。

验收标准：

1. 用户能在首屏识别待处理、SLA 风险和待审批事项。
2. 点击任务总是打开右侧生命周期抽屉。
3. 所有任务事实状态均经由 Mock API 创建或更新。
4. 会话、首页、任务、审计和渠道的任务状态一致。
5. 任务流转受审批、依赖、权限和状态规则约束。
6. 慢响应、失败、冲突和部分失败均有明确反馈。
7. 页面不使用固定三栏和过密的常驻筛选区。
