# 企业数字员工任务控制台设计

## 目标与边界

任务控制台服务于生产运营与受控执行，不是通用项目管理或团队协作工具。它帮助运营人员处置数字员工执行中的高优任务、审批请求、人工接管和风险异常，并保留完整的审计证据。

任务生命周期为：

```text
告警、会话或工作流触发
  -> 任务受理
  -> 数字员工执行
  -> 人工审批、接管或异常处置
  -> 完成与审计归档
```

本期只保留四个核心模块：

1. **任务处置**：识别、筛选和打开需要处理的任务。
2. **执行控制**：查看数字员工执行状态、关键步骤、失败原因，并暂停或重试。
3. **人工治理**：完成审批、人工接管、策略拦截和 SLA 升级。
4. **审计追溯**：回溯来源、关键操作、执行证据和结果。

不包含项目管理能力：任务模板、附件管理、评论协作、独立时间线、复杂标签体系、批量改优先级、批量归档和面向项目排期的编辑能力。

## 已确认原则

- 使用单一任务主面板，不采用固定三栏。
- 点击任务按需打开右侧详情抽屉。
- 首屏优先展示需要人工处置的任务，而不是统计图表。
- 靛蓝 `#4f46e5` 只用于品牌、选中状态和主操作；成功、风险和失败使用独立语义色。
- 任务、执行、审批和审计由统一 Mock 领域状态维护，页面不能维护独立的任务事实状态。

## 页面结构

```text
任务控制台
├─ 行动摘要：待处理 / 待审批或接管 / 风险异常
├─ 工作工具栏：搜索、状态、负责人、风险、筛选、新建
├─ 任务主面板：处置看板或紧凑列表
└─ 右侧任务抽屉：概览、执行、人工治理、审计
```

### 行动摘要

顶部只保留三个可点击的任务摘要：

| 摘要 | 定义 | 点击结果 |
| --- | --- | --- |
| 待处理 | 需要当前用户开始、确认或分派的任务 | 过滤待处理任务 |
| 待审批或接管 | 等待审批、双签或人工接管的任务 | 过滤等待人工动作任务 |
| 风险异常 | SLA 超时、临期、执行失败或策略拦截的任务 | 过滤风险任务并按紧急程度排序 |

不显示成功率、任务总数、P0 总数、风险地图或其他非行动型 KPI。任务数量可作为摘要卡内的辅助信息，不能替代处置入口。

### 工作工具栏

常驻控件固定为：

```text
[搜索任务、编号、来源] [状态] [负责人] [风险] [筛选]                    [新建任务]
```

“筛选”弹层只提供生产运营相关条件：优先级、数字员工、来源、审批状态、是否阻塞和归档状态。已选条件显示为可单独清除的 Chip。页面默认不提供批量编辑；仅在监管需要时，可保留受权限控制的批量“确认归档”。

## 任务主面板

### 默认处置看板

默认采用五段生命周期看板：

```text
待处理 -> 执行中 -> 等待人工动作 -> 风险异常 -> 已完成
```

- **待处理**：等待受理、分派或开始执行。
- **执行中**：数字员工正在运行，展示执行进度或当前步骤。
- **等待人工动作**：等待审批、双签或人工接管。
- **风险异常**：执行失败、SLA 超时、依赖阻塞或策略拦截。
- **已完成**：任务已经完成，保留短期可见；归档记录通过筛选查看。

任务卡只显示处置必需的信息：

```text
优先级与 SLA
任务标题
当前阶段与数字员工
责任人
风险或人工动作标记
来源（告警、会话或工作流）
```

卡片点击打开详情抽屉。拖拽是状态流转请求入口，不直接修改前端状态；审批未通过、依赖未满足、权限不足或阶段不允许时，保留原状态并显示 API 返回的原因。

### 紧凑列表

列表适合高密度巡检与搜索，列为：任务编号与标题、当前阶段、优先级、负责人、数字员工、SLA 和最后更新。行内唯一操作是“打开详情”。

不单独提供时间线视图；生命周期事件在任务详情抽屉的审计标签中查看，避免将同一信息拆分到多个页面入口。

## 右侧任务详情抽屉

抽屉是唯一的深度操作入口。顶部展示标题、编号、优先级、当前阶段、SLA 和任务来源。

| 标签 | 内容 |
| --- | --- |
| 概览 | 任务目标、当前阶段、责任人、数字员工、SLA、来源和只读关联对象 |
| 执行 | 当前步骤、关键工具调用、执行结果、失败原因、暂停和重试记录 |
| 人工治理 | 审批与双签、策略拦截、人工接管、升级记录和处置原因 |
| 审计 | 创建、流转、审批、接管、执行和完成的时间序列证据 |

抽屉底部根据任务阶段只展示一个主操作：

| 阶段 | 主操作 |
| --- | --- |
| 待处理 | 开始执行或分派 |
| 等待人工动作 | 批准、驳回或人工接管 |
| 风险异常 | 重试执行或人工接管 |
| 执行中 | 暂停任务 |
| 已完成 | 确认归档 |

拒绝、接管、强制归档等不可逆动作必须要求填写原因并二次确认。资产、依赖、关联会话和工作流只读展示，编辑通过其所属业务模块完成。

## 视觉与组件规范

### 字体

- 页面标题：16px / 600。
- 区域标题：14px / 600。
- 任务标题：14–15px / 500–600。
- 列表正文：13px / 400。
- SLA、时间和辅助信息：11–12px。
- 运行 ID、哈希等技术标识：10–11px 等宽字体。

常规内容不使用 9px 或 10px，保证值班和运营场景的快速阅读。

### 颜色与交互

- 靛蓝用于主按钮、选中筛选和链接；筛选选中态使用浅靛蓝背景，不使用大面积实心色块。
- 绿色表示执行成功和完成；黄色表示临期、待处理和需关注；红色只表示超时、失败、阻塞和拒绝。
- 卡片使用白底、12px 圆角、细边框和轻阴影；悬停只轻微提升。
- 默认不展示多个行内按钮，避免任务卡成为操作面板。

## Mock API 设计

### 核心接口

```text
GET    /api/tasks
POST   /api/tasks
GET    /api/tasks/:id
POST   /api/tasks/:id/transition
POST   /api/tasks/:id/approve
POST   /api/tasks/:id/takeover
POST   /api/tasks/:id/retry
GET    /api/tasks/:id/audit
POST   /api/mock/reset
```

`GET /api/tasks` 支持状态、负责人、风险、来源、审批状态、优先级和归档状态筛选。写接口完成状态规则校验并返回任务与新增审计事件；前端刷新相关查询，不以本地副本作为最终结果。

### 任务模型

```ts
{
  id, code, title, lifecycleStage, priority,
  assignee, agent, source, sla,
  execution, governance, links, auditEvents, version
}
```

- `source`：告警、会话、工作流或手工创建。
- `sla`：截止时间、剩余时间、风险等级与升级状态。
- `execution`：运行 ID、当前步骤、关键结果、错误与重试次数。
- `governance`：审批策略、签署人、策略拦截、人工接管和处置原因。
- `links`：关联会话、告警、工作流和 CMDB 资产，只读。
- `version`：模拟并发操作冲突。

### 状态规则

```text
待处理 -> 执行中
执行中 -> 等待人工动作 / 风险异常 / 已完成
等待人工动作 -> 执行中 / 待处理
风险异常 -> 执行中 / 等待人工动作
已完成 -> 已归档
```

API 负责阻止无效流转：审批未通过、依赖阻塞、权限不足、策略拦截或版本冲突时返回明确业务错误与建议动作。

## 必要的 Mock 场景

保留以下场景以验证受控执行闭环：

1. P0 已超时任务，需要升级或人工接管。
2. 双签待审批任务，审批完成后才能继续执行。
3. 数字员工执行失败任务，展示错误证据并允许重试。
4. 被依赖阻塞任务，禁止完成并提示阻塞源。
5. 会话或工作流创建任务后，任务页、首页和审计流同步更新。
6. 无权限审批、慢响应、请求失败与版本冲突。

Mock 至少模拟 80ms、800ms 和 3s 三档延迟。提交期间禁用重复操作；请求失败和部分结果必须在当前操作位置展示原因与重试入口。

## 数据流与验收

```text
用户操作
  -> 任务 Mock Mutation
  -> 统一领域状态
  -> 任务页面、首页摘要、会话上下文、审计流和渠道通知同步刷新
```

验收标准：

1. 用户在首屏识别待处理、待审批接管和风险异常任务。
2. 点击任务始终打开右侧抽屉，不出现固定详情栏。
3. 创建、流转、审批、接管、暂停和重试均通过 Mock API。
4. 会话、工作流、任务页、首页和审计流展示一致的任务状态。
5. 审批、依赖、权限和策略规则能阻止无效操作。
6. 页面不保留通用项目管理功能和非行动型 KPI。
