# 工作区控制面设计

## 目标

将“工作区”从展示型多工作区页面升级为企业级数字员工平台的操作控制面。工作区负责业务责任域内的成员、资源、策略、配额、运行治理和审计；租户负责组织、订阅、全局安全基线与根级隔离。

## 边界与层级

```text
Tenant（组织、订阅、根级安全边界）
└── Workspace（成员、资源、策略、配额、审计）
    └── Environment（sandbox、staging、production）
        └── Resource bindings（Agent、工作流、知识、技能、模型、渠道）
```

系统设置定义身份源、KMS、供应商准入、全局安全基线和审计保留。模型、渠道、知识、技能中心保留专业配置职责；工作区只管理资源归属、可用范围、环境与策略约束。

## 导航与职责

工作区页面包含以下固定分区：

1. 概览：健康度、风险、待办、成本与配额摘要。
2. 成员与权限：成员、角色绑定、临时授权、访问复核与 MFA。
3. 资源目录：资源归属、环境绑定、允许使用范围与依赖影响。
4. 环境与发布：环境、晋级、灰度、回滚和发布审批。
5. 工作区策略与合规：数据、网络、工具、模型/渠道、地域、保留、例外。
6. 配额与成本：席位、并发、Token、预算、成本与告警。
7. 运行治理：人工接管、熔断、停用、风险事件与处置。
8. 工作区审计：可检索的成员、资源、策略、发布与运行证据。
9. 工作区设置：基本信息、负责人、通知与生命周期。

## P0

- 定义 Tenant、Workspace、Environment、Membership、Role、Binding、AuditEvent 等领域类型。
- 为每个请求建立工作区上下文，Query Key 与请求头均以当前工作区隔离。
- Mock API 使用身份、成员关系与权限校验工作区范围；拒绝跨工作区读写。
- 实现工作区创建、冻结、归档、负责人移交与审计。
- 实现成员邀请、角色变更、移除、临时访问和访问复核。
- 实现资源目录与资源绑定，支持依赖影响查询。
- 实现工作区审计事件查询和筛选。

## P1

- 实现环境、发布审批、灰度、回滚与环境准入。
- 实现工作区策略与合规例外流程。
- 实现配额、预算、成本归集、阈值告警。
- 实现运行治理事件、人工接管、熔断和停用。

## P2

- 实现受控模板分发、只读共享、审批式跨工作区授权和迁移。
- 实现工作区运营评分、治理报告和审计导出。
- 实现外协访问到期、自动回收与强化隔离策略。

## 数据流与安全

前端切换工作区后更新 WorkspaceContext，并使所有查询失效。API 客户端随请求发送工作区上下文；Mock API 使用登录身份的成员关系及权限校验访问。请求体中的 workspaceId 只能作为一致性校验输入，不能决定实际作用域。写操作必须记录 actor、workspace、目标、原因、结果与关联 ID。

## 验收与测试

- 选择工作区后，所有工作区页及受控中心的查询缓存按工作区隔离。
- 非成员不能读取成员、资源、策略、审计或环境数据。
- 只读成员不能执行创建、绑定、发布、冻结、归档等写操作。
- 创建、成员变更、策略变更、发布、运行治理均产生审计事件。
- 删除/冻结前能返回资源依赖影响，并阻止不安全操作。
- Web 类型检查、构建、Mock API 测试和工作区交互测试通过。
