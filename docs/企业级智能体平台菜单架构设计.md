# 企业级智能体平台 · 信息架构设计文档

> 一级菜单共 **16 个**（原始 11 个 + 补充 5 个），按"供给层 - 编排层 - 交互层 - 交付层 - 质量层 - 安全层 - 生态层 - 管理层"八层组织。

---

## 一、首页（Dashboard）

**定位**：全局信息聚合与快速入口
**职责**：为登录用户提供个性化的运营总览和任务导航

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 数据总览 | 会话量、任务完成率、活跃智能体数、Token消耗等核心指标卡片 | 一眼掌握平台整体运营状态 |
| 我的待办 | 待处理任务、审批、告警聚合 | 无需跳转多个模块即可处理紧急事项 |
| 快捷入口 | 常用智能体/工作流收藏、最近使用记录 | 提升高频操作效率 |
| 消息通知 | 系统公告、协作@提醒、任务完成通知 | 及时获知平台动态 |

**做什么**：只做展示、聚合、跳转
**边界**：不承载业务操作与深度编辑；不做审批流转的实际处理（跳转至对应模块处理）

---

## 二、会话（Chat / Session）

**定位**：人与智能体的实时交互入口
**职责**：承载单轮/多轮同步对话场景，是最基础的人机交互界面

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 对话窗口 | 多轮上下文对话、流式输出、多模态输入（文本/图片/文件） | 像聊天一样直接与智能体交流 |
| 会话历史 | 历史会话列表、检索、置顶、归档 | 随时找回过去的对话记录 |
| 会话内工具调用 | 临时调用知识库、技能、切换模型 | 单次对话中灵活扩展智能体能力 |
| 转人工/协作 | 智能体处理受限时无缝转接人工客服 | 保障复杂问题有兜底处理 |
| 分享与导出 | 会话链接分享、导出为文档 | 便于沉淀与传播对话成果 |

**做什么**：处理"实时、同步、轻量交互"场景
**边界**：不承载多步骤可编排的自动化流程（属于工作流职责）；不做批量异步执行（属于任务职责）

---

## 三、任务（Task）

**定位**：异步、批量、可追踪的执行单元管理中心
**职责**：管理长耗时、无需实时等待、可能无人值守的执行任务

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 任务列表 | 全部任务的状态视图（排队/执行中/成功/失败/重试） | 集中掌控所有后台任务进度 |
| 任务创建 | 手动发起批量任务（如批量文档处理、数据分析） | 一次性提交大批量处理需求 |
| 定时任务 | Cron定时触发配置 | 实现"设置后自动执行"的自动化 |
| 任务详情与日志 | 执行过程可视化、错误堆栈查看 | 快速定位任务失败原因 |
| 结果管理 | 结果预览、下载、重试、终止 | 灵活处置任务产出物 |

**做什么**：管理"异步执行单元"的全生命周期
**边界**：区别于会话的同步交互；任务本身的执行逻辑通常来自智能体或工作流的调用，任务模块不定义业务逻辑，只做调度与追踪

---

## 四、智能体（Agent）

**定位**：具备自主推理决策能力的AI角色实体的构建与管理中心
**职责**：将模型、知识、技能组装成可独立完成任务的智能体

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 智能体广场 | 智能体列表、分类、搜索 | 快速找到符合需求的智能体 |
| 智能体创建/编辑 | 人设Prompt配置、能力挂载（模型/知识库/技能） | 零代码/低代码构建专属智能体 |
| 调试与测试（Playground） | 实时对话调试、多轮追踪、参数微调 | 上线前验证智能体表现 |
| 版本管理 | 版本快照、灰度发布、回滚 | 安全迭代不影响线上稳定性 |
| 权限与发布 | 可见范围、使用权限、发布渠道绑定 | 控制智能体的分发范围 |
| 记忆管理 | 长期记忆、用户画像、对话摘要配置 | 让智能体具备个性化与连续性 |

**做什么**：智能体是"能力的组装体"与"自主决策的执行主体"
**边界**：不生产模型能力（依赖模型中心）、不生产知识（依赖知识中心）、不生产原子技能（依赖技能中心）；与工作流的区别在于——智能体强调"自主推理决策"，工作流强调"确定性流程编排"

---

## 五、工作流（Workflow）

**定位**：确定性、可视化的多步骤流程编排引擎
**职责**：将多个能力节点按照预设逻辑串联，实现可控、可预测的自动化流程

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 流程画布 | 拖拽式编排、条件分支、循环、并行节点 | 无代码搭建复杂业务流程 |
| 节点库 | 内置节点（智能体/技能/模型/API/代码块） | 灵活组合不同类型的处理单元 |
| 变量与数据流 | 节点间数据传递、变量映射、格式转换 | 保证流程各环节数据正确流转 |
| 触发器配置 | 手动/定时/事件（Webhook）触发 | 支持多种流程启动方式 |
| 调试与发布 | 单步调试、日志追踪、版本发布 | 保障流程上线前的稳定性 |

**做什么**：偏向"确定性逻辑编排"，可作为智能体的"骨架"或独立自动化流程
**边界**：不直接管理原子能力（模型/技能/知识）的注册，只做调用编排；很多平台支持工作流中嵌入智能体节点，反之智能体也可调用子工作流，二者互为补充而非互斥

---

## 六、知识中心（Knowledge Center）

**定位**：企业知识资产的统一管理与检索底座
**职责**：负责知识的采集、处理、存储、检索全链路

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 知识库管理 | 知识库创建、分类、权限设置 | 按业务/部门隔离管理知识资产 |
| 数据接入 | 文件上传、数据库同步、网页抓取、API接入 | 多渠道快速汇聚企业知识 |
| 文档处理 | 清洗、切片（Chunking）、向量化、OCR | 将非结构化内容转为可检索资产 |
| 检索策略配置 | 召回算法、重排（Rerank）、混合检索 | 调优知识检索的准确率 |
| 知识更新维护 | 版本管理、失效检测、增量更新 | 保持知识库的时效性与准确性 |

**做什么**：只负责知识的"存储-处理-检索"能力供给
**边界**：不负责知识如何被使用（使用逻辑在智能体/工作流中配置调用）

---

## 七、技能中心（Skill Center）

**定位**：可复用能力资产（Skill / MCP / Tool 三类）的统一管理仓库
**职责**：注册、管理、分发可被智能体/工作流调用的各类能力，按能力形态分层治理

技能中心不是单一同质的能力池，而是包含 **三类性质不同的能力资产**，三者粒度和调用方式均不同，需分类管理：

| 类型 | 本质 | 粒度 | 典型形式 |
|---|---|---|---|
| **Skill（技能包）** | 过程性知识/工作方法的封装，通常是"指令+资源文件"的组合，教会智能体如何完成一类任务 | 中～粗粒度，可包含多步骤方法论 | Prompt模板+参考文档+脚本代码的打包（如"生成PPT的技能"“财务分析技能”） |
| **MCP（协议化外部连接）** | 通过标准协议（Model Context Protocol）接入的外部系统/服务，提供一组相关联的工具集 | 服务级，一个MCP Server通常暴露多个Tool | 企业微信MCP、Salesforce MCP、GitHub MCP |
| **Tool（原子工具/函数）** | 单一输入输出、明确Schema定义的原子函数调用 | 最小粒度，单一确定性功能 | 查天气API、计算器函数、发送邮件接口 |

**二级菜单设计：**

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| **Skill 管理** | Skill打包（指令+资源+脚本）、市场浏览、版本迭代、效果测试 | 沉淀可复用的"业务方法论"，让智能体具备某类任务的完整工作方式 |
| **MCP 管理** | MCP Server接入配置、连接测试、权限范围（Scope）设置、可用工具列表预览 | 一次接入即可让智能体获得一整套外部系统能力（如飞书全家桶） |
| **Tool 管理** | 原子工具注册、输入输出Schema定义、代码/低代码开发、Function Calling测试 | 将企业内部API/函数快速封装为智能体可调用的确定性能力 |
| **能力市场** | Skill/MCP/Tool统一检索、分类浏览、内置+自定义+第三方来源聚合 | 像应用商店一样统一发现所有可用能力，无需关心底层类型差异 |
| **调用权限与审计** | 按类型/按能力的调用鉴权、频率限制、日志审计 | 精细化防止未授权调用带来的安全风险，MCP因涉及外部系统权限更需重点管控 |

**三者的调用关系与边界**：
- **Skill 依赖 Tool/MCP**：一个Skill内部往往会调用若干Tool或MCP能力来完成具体步骤，Skill是"方法+工具的组合编排"，而Tool/MCP是被组合的"零件"
- **MCP 是 Tool 的批量供给渠道**：一个MCP Server本身不是一个工具，而是通过协议暴露出的一组Tool集合；管理MCP本质是管理"一批工具的接入源"
- **Tool 是最终被模型Function Calling调用的最小单元**：无论能力来自内置开发还是MCP接入，最终被智能体调用时都会被归一化为Tool的Schema形式

**做什么**：技能中心是"能力资产"的标准化封装、接入与仓储中心，覆盖从最小原子能力（Tool）、到批量外部集成（MCP）、再到复合方法论（Skill）的完整能力谱系
**边界**：不涉及流程编排（工作流职责）和自主决策（智能体职责）——技能中心只做能力的"生产、接入与供给"，具体如何组合调用这些能力，由智能体或工作流在消费侧决定

---

## 八、模型中心（Model Center）

**定位**：AI模型资源的统一接入与治理平台
**职责**：管理模型的接入、配置、评测、成本

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 模型接入 | 自研模型、第三方API（如OpenAI/Anthropic）、开源模型部署 | 统一管理多来源模型资源 |
| 参数配置 | 温度、Top-P、最大Token、系统提示词模板 | 精细调控模型输出行为 |
| 模型评测 | 效果对比、A/B测试、Benchmark跑分 | 科学选型最适合业务的模型 |
| 配额与成本管理 | 调用限流、预算告警、成本分摊 | 控制AI使用成本，避免超支 |
| 模型监控 | 可用性、延迟、错误率监控 | 保障模型服务的稳定性 |

**做什么**：只负责模型能力的"供给侧"治理
**边界**：不涉及模型具体如何被业务调用（消费侧逻辑在智能体/工作流/会话中）

---

## 九、渠道中心（Channel Center）

**定位**：智能体对外分发和触达的接入管理
**职责**：打通智能体与各类外部触点的连接与协议适配

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 渠道接入 | 网页、企业微信、飞书、钉钉、短信、API、Webhook等 | 一处配置，多端触达用户 |
| 渠道绑定 | 智能体/工作流与渠道的映射关系 | 灵活控制不同渠道对应的服务能力 |
| 消息适配 | 格式转换、富媒体消息适配 | 保证跨渠道消息体验一致性 |
| 限流与鉴权 | 渠道级流控、身份校验 | 防止渠道被恶意调用 |

**做什么**：只负责"入口/出口"的连接与协议转换
**边界**：不涉及业务逻辑处理（业务逻辑在智能体/工作流中）

---

## 十、工作区（Workspace）

**定位**：多租户/多团队的资源隔离与协作空间
**职责**：为组织内不同团队/项目提供资源隔离与协作边界

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 工作区管理 | 创建、切换、归档工作区 | 按团队/项目划分独立的工作空间 |
| 成员与协作 | 成员邀请、角色分配、协作编辑 | 支持团队协同构建智能体资产 |
| 资源归属 | 智能体/知识库/工作流的工作区归属管理 | 明确资源所有权，避免混乱 |

**做什么**："容器级"的组织维度管理
**边界**：本身不承载具体业务功能，只为上述所有模块提供隔离边界

---

## 十一、设置（Settings）

**定位**：平台级/账号级配置与治理中心
**职责**：管理平台运行所需的全局性、合规性配置

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 用户与权限 | RBAC角色管理、组织架构同步（SSO/LDAP） | 精细化控制谁能做什么 |
| 安全合规 | 审计日志、数据脱敏规则、合规报告 | 满足企业安全合规审查要求 |
| 计费与配额 | 套餐管理、用量统计、账单 | 掌控平台使用成本 |
| 系统参数 | 全局默认配置、集成配置 | 统一管理平台底层参数 |

**做什么**：只做"平台治理类"配置
**边界**：不涉及具体业务对象（智能体、工作流等）的内容配置

---

## 十二、观测中心（Observability）★补充

**定位**：全链路运行时监控与问题诊断中心
**职责**：对平台运行时状态进行实时观测、追踪与告警

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 调用链追踪（Trace） | 请求经过的节点、模型、工具及耗时可视化 | 快速定位问题发生在哪个环节 |
| 实时监控大盘 | QPS、延迟、成功率、Token消耗、报错率 | 实时掌握系统健康状况 |
| 日志检索 | 全文检索、多维筛选 | 精准排查具体问题日志 |
| 告警配置 | 阈值告警、多渠道通知（邮件/短信/IM） | 问题发生第一时间获知 |
| 成本归因分析 | 按智能体/工作区/渠道拆解成本 | 明确成本消耗的具体来源 |

**做什么**：只做"事后/实时观察与诊断"
**边界**：不做业务配置修改；区别于首页的总览性展示，这里更偏向工程级排障，面向技术/运维人员

---

## 十三、评测中心（Evaluation）★补充

**定位**：智能体/工作流质量的量化验证体系
**职责**：为业务应用层（而非模型层）提供效果评测与回归保障

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 测试集管理 | 人工标注、自动生成测试用例 | 沉淀标准化的评测基准 |
| 效果评测 | 准确率、幻觉率、任务完成率打分 | 量化衡量智能体实际表现 |
| Badcase管理 | 问题案例收集、标注、回归测试 | 持续发现并修复问题场景 |
| A/B实验 | 不同版本/Prompt效果对比 | 数据驱动地优化迭代方向 |

**做什么**：针对具体智能体/工作流的应用层效果评测
**边界**：区别于模型中心的"模型层评测"（Benchmark跑分），这里评测的是"业务实际使用效果"

---

## 十四、安全护栏中心（Guardrails）★补充

**定位**：内容安全与风险防控中心
**职责**：对智能体的输入输出进行实时安全审核与拦截

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 内容审核策略 | 敏感词、合规过滤规则配置 | 自定义符合行业监管的审核标准 |
| 攻击防御 | Prompt注入检测、越狱攻击防御 | 抵御恶意用户对智能体的攻击 |
| 数据脱敏 | 敏感信息（身份证/手机号等）自动脱敏 | 防止敏感数据泄露 |
| 滥用行为拦截 | 频率限制、异常行为识别 | 防止资源被滥用 |

**做什么**：内容/行为层面的实时拦截与规则引擎配置
**边界**：与设置中心的静态权限管理不同，这里针对"内容与行为"做动态、精细化的风控，尤其适用于金融、医疗等强监管行业

---

## 十五、应用中心（App Center）★补充

**定位**：智能体/工作流的产品化封装与分发市场
**职责**：将底层能力包装成面向最终用户的可直接使用的应用

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| 应用编排 | 组合多个智能体+工作流+自定义UI表单 | 无需开发即可搭建业务应用 |
| 应用市场 | 内部应用商店，员工自助订阅使用 | 像用App一样便捷使用AI能力 |
| UI定制 | 表单、按钮、交互组件可视化配置 | 打造贴合业务场景的专属界面 |

**做什么**：完成从"能力"到"可用产品"的最后一公里封装
**边界**：智能体/工作流是"能力"本身，应用是面向最终用户的产品化封装；渠道中心解决"从哪进来"，应用中心解决"进来之后长什么样、怎么交互"

---

## 十六、开发者中心（Developer Center）★补充

**定位**：面向外部开发者的能力开放平台
**职责**：为二次开发和系统集成提供标准化接口与文档

| 二级菜单 | 核心能力 | 提供用户的能力 |
|---|---|---|
| API管理 | API Key创建、权限范围设置 | 安全地对外开放平台能力 |
| 开发文档 | API文档、SDK下载、示例代码 | 降低第三方开发者接入门槛 |
| Webhook配置 | 事件订阅、回调地址管理 | 实现与外部系统的事件联动 |
| 接入审核 | 第三方应用接入申请与审批 | 保障平台开放的安全可控性 |

**做什么**：面向B端开发者的能力开放与集成支持
**边界**：区别于渠道中心（面向C端用户触达），这里面向开发者做API级别的二次开发

## 整体架构分层图

```
┌─────────────────────────────────────────────────────┐
│  管理层：工作区（隔离）+ 设置（治理）+ 首页（总览）      │
├─────────────────────────────────────────────────────┤
│  生态层：开发者中心（对外开放）                          │
├─────────────────────────────────────────────────────┤
│  安全层：安全护栏中心（内容与行为风控）                   │
├─────────────────────────────────────────────────────┤
│  质量层：评测中心（效果验证）+ 观测中心（运行时监控）      │
├─────────────────────────────────────────────────────┤
│  交付层：应用中心（产品化封装）+ 渠道中心（对外分发）      │
├─────────────────────────────────────────────────────┤
│  交互层：会话（实时同步）+ 任务（异步批量）               │
├─────────────────────────────────────────────────────┤
│  编排层：智能体（自主决策）+ 工作流（确定性流程）          │
├─────────────────────────────────────────────────────┤
│  供给层：模型中心 + 知识中心 + 技能中心（原子能力）        │
└─────────────────────────────────────────────────────┘
```

## 核心设计原则

1. **能力供给与能力消费分离**：模型/知识/技能只负责"生产"能力，智能体/工作流负责"组装消费"
2. **实时交互与异步执行分离**：会话处理同步场景，任务处理异步场景
3. **确定性编排与自主决策分离**：工作流强调流程可控，智能体强调自主推理
4. **能力与产品分离**：智能体/工作流是能力，应用中心才是面向最终用户的产品形态
5. **治理贯穿始终**：安全护栏、观测、评测三者共同构成企业级平台的"信任基座"，是区别于C端产品的核心壁垒
