## 1. 平台定位

数字员工平台是面向企业组织的 **AI Agent 编排与治理控制面**：将大模型、企业知识（RAG）、技能/MCP/工具与工作流编排为可被人类员工调用的**岗位数字员工**，在受控边界内完成客服、SRE、运维、合规、研发等重复性工作。

### 核心卖点

| # | 卖点 | 说明 |
|---|---|---|
| 1 | 岗位数字员工全生命周期 | 岗位配置 → 能力装配 → 评测上岗 → 运行运营 → 审计证据 |
| 2 | 受控执行与双签 | 生产写操作身份绑定双签；职责分离；审计用户只读 |
| 3 | 能力资产统一治理 | 模型 / 知识 / 技能 / 记忆 / 消息渠道分控制面，数字员工只引用已发布版本 |
| 4 | 零信任持续验证 | 按身份、资源、环境、数据范围决策 allow / mask / approval / deny |
| 5 | 等保 3 + ISO 27001 目标 | 双审计、凭据掩码、数据出境策略、沙箱隔离（目标底座） |
| 6 | Go + Python 双栈（目标） | 业务控制面 Go；Agent/RAG Python；Connect-RPC 互通 |

## 2. 当前实现架构（L0）

### 2.1 工程结构

```text
digital-employee-platform/
├── README.md
├── docs/                         # 视觉规范、规格与实施计划
└── frontend/                     # pnpm workspace
    ├── web/                      # React 18 + Vite 5 控制台
    └── packages/
        ├── api/                  # @de/web-api — ApiClient + mock.ts
        ├── types/                # @de/web-types — 领域类型
        ├── ui/                   # @de/web-ui — Button / Badge / KpiCard …
        ├── utils/                # @de/web-utils
        └── hooks/                # @de/web-hooks
```

- 默认 `VITE_USE_MOCK !== 'false'` → 注入本地 Mock Handler  
- 状态：Zustand（auth / ui / workspace）+ TanStack Query  
- 路由：`frontend/web/src/App.tsx`（lazy + `ProtectedRoute` + `AppLayout`）  
- 设计壳：`de-employee-page` / `de-employee-shell` / Tabs / KPI；品牌色 `#4f46e5`

### 2.2 信息架构（与侧栏一致）

```text
运营总览 (/home)
协作：专家协作 (/copilot) → 任务中心 (/tasks)
编排：数字员工 (/agents) → 工作流程 (/workflows)
能力：模型服务 → 知识中心 → 技能中心 → 记忆中心 → 消息渠道
账号菜单：工作区 · 平台设置（含访问控制 / 持续验证 / 审计中心）
```

控制型模块二级菜单统一顺序：

`概览或资产 → 接入与配置 → 验证与发布 → 运行与处置 → 治理与审计`

首次登录向导（`OnboardingGuide` v2）：**能力接入 → 编排上岗 → 受控运营**。

## 3. 领域控制面与依赖（L1）

### 3.1 能力引用关系

```text
                    ┌────────────┐
                    │ 运营总览    │
                    └─────┬──────┘
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   ┌─────────┐      ┌─────────┐       ┌─────────┐
   │专家协作  │◄────►│任务中心  │       │消息渠道  │
   └────┬────┘      └────┬────┘       └────┬────┘
        │                │                 │
        ▼                ▼                 │
   ┌─────────────────────────────────┐     │
   │ 数字员工（岗位边界 · 引用已发布） │◄────┘
   └───┬─────────┬─────────┬─────────┘
       ▼         ▼         ▼
   工作流程    模型服务   知识/技能/记忆
       │         │         │
       └─────────┴─────────┘
                 │
        ┌────────┴────────┐
        ▼                 ▼
   访问控制 / 持续验证   审计中心
        └────────┬────────┘
                 ▼
            平台设置壳
```

**原则：**

- 模型、知识、技能、工具、工作流、渠道由**各自控制面**治理版本与发布。  
- 数字员工只装配**已发布**能力版本，保留评测、上岗、运行证据。  
- 长期记忆仅产出**知识候选**，审核通过后才进入知识资产。  
- 工作区提供业务域边界；RBAC / 零信任 / 审计不在工作区重复建面。

### 3.2 角色边界

| 角色 | 可见能力 |
|---|---|
| `user` | 专家协作、任务、已授权数字员工、工作流、知识、技能、记忆 |
| `admin` | 上述 + 模型、消息渠道、工作区、平台设置与全部治理写操作 |
| `auditor` | 持续验证事件与审计中心只读；可导出脱敏证据；不参与签发/配置 |

### 3.3 安全规则（Mock 已覆盖语义）

- 请求携带工作区上下文；跨工作区引用拒绝；查询缓存按工作区隔离。  
- 凭据仅返回引用/掩码，不回明文。  
- 已发布路由/投递策略与被引用能力受依赖保护，不可直接删除。  
- 零信任决策：`allow` / `mask` / `approval_required` / `deny` + obligations。  
- 受控双签：登录用户 ID + 职责席位；顺序、重复签发、SoD 校验；审计员不签发。  
- 受限数据出口：模型/渠道策略做地域与出口校验，高风险写关联审计。

### 3.4 关键执行链路（产品语义）

```text
用户（专家协作）
  → 身份与工作区校验
  → 任务/会话工作卡
  → 模型路由（等级 · 预算 · 出境策略）
  → RAG（知识 + 记忆上下文）
  → 工作流 / 技能·MCP·工具（受策略约束）
  → 写操作：双签门禁 + 零信任评估
  → 审计事件（关联 correlationId）
  → 消息渠道投递（主备降级 / 死信）
  → 回写会话证据与任务状态
```

## 4. 目标技术架构（L2，选型锁定）

> 以下为生产目标栈；当前仓库以 Mock 验证控制面契约，后端服务不在本仓交付。

### 4.1 双栈分层

| 栈 | 语言 | 用途 | 代表 |
|---|---|---|---|
| 业务栈 | Go 1.22+ | API、网关、RBAC、审计、Temporal Worker、DB | Gin |
| AI 栈 | Python 3.12 | LangGraph Agent、LlamaIndex、RAG、Skill/MCP | LangGraph |
| 互通 | Connect-RPC | 一套 protobuf → Go/Python SDK；gRPC + REST | Envoy |

### 4.2 数据与 AI

| 类型 | 选型 | 备注 |
|---|---|---|
| RDB | PostgreSQL 16 | openGauss 备选 |
| 向量 | Milvus 2.4 | HNSW；独立部署 |
| 图 | NebulaGraph 3.x | 知识图谱 |
| 缓存 | Redis 7 | |
| MQ | Kafka 3.7+ KRaft | |
| 检索/日志 | OpenSearch 2.x | 统一日志检索 |
| Embedding / Rerank | BGE-M3 / bge-reranker-large | |
| 文档解析 | Tika + PaddleOCR + PyMuPDF | |

### 4.3 前端（已实现）

| 组件 | 选型 |
|---|---|
| 框架 | React 18 + Vite 5（不用 Next.js） |
| 路由 | React Router 6 |
| 状态 | Zustand 4 + TanStack Query 5 |
| 画布 | React Flow 11 |
| 包管理 | pnpm Workspace |

### 4.4 基础设施与可观测（目标）

- K8s 1.30+、Istio mTLS、ArgoCD、Harbor、Vault、Nacos  
- 沙箱：**gVisor（不可替换）**  
- Prometheus + OpenTelemetry + Jaeger + Grafana + OpenSearch  

### 4.5 多区域与合规（目标）

- cn-east / cn-south 主动-主动；境外仅作受限 Provider 出口区  
- 默认数据不出境；P0/P1 可出境需审计与配额  
- 写动作 100% 双人复核语义；SignedLog → SIEM
