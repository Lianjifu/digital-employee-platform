# 企业级数字员工平台视觉设计规范

版本：3.2
更新时间：2026-07-18  
适用范围：Web 控制台、会话工作台、任务控制台、智能体、工作流、知识、技能、模型、渠道与设置模块

## 1. 设计定位

平台是面向企业生产运营与受控执行的数字员工控制台。界面应优先表达：

1. 当前发生了什么；
2. 用户下一步可以做什么；
3. 操作是否需要审批、是否存在风险；
4. 操作结果能否追溯。

视觉参考现代 SaaS 产品（Linear、Vercel、Stripe）：克制、清晰、稳定、可扫描。避免装饰性渐变、过度发光、AI 风格插画和无业务价值的指标堆叠。

## 2. 视觉语言

### 2.1 色彩

采用“中性灰阶 + 单一品牌色 + 语义状态色”。品牌色用于主要行动、当前选中和焦点，不承担风险表达。

| 用途 | Token | 颜色 |
| --- | --- | --- |
| 品牌主色 | `--brand` | `#4f46e5` |
| 品牌悬浮 | `--brand-hover` | `#4338ca` |
| 品牌浅底 | `--brand-light` | `#eef2ff` |
| 页面背景 | `--bg-elevated` | `#f8fafc` |
| 内容表面 | `--surface-1` | `#ffffff` |
| 悬浮背景 | `--bg-hover` | `#f1f5f9` |
| 边框 | `--border` | `#e2e8f0` |
| 主文字 | `--text` | `#0f172a` |
| 次级文字 | `--text-secondary` | `#334155` |
| 弱化文字 | `--text-muted` | `#64748b` |
| 成功 | `--success` | `#10b981` |
| 警告 | `--warning` | `#f59e0b` |
| 错误/危险 | `--danger` | `#ef4444` |
| 信息 | `--info` | `#0ea5e9` |

规则：

- 红色只表示错误、危险、超时和破坏性操作；橙色只表示待审批、风险复核和预算预警。
- 品牌色不与风险等级混用。
- 主按钮不使用紫色渐变；默认使用实体品牌色、轻阴影和悬浮微上移。
- 状态色必须同时配合文字或图标，不依赖颜色单独传达含义。

### 2.2 圆角、边框与阴影

- 小控件：`4px–6px`；按钮、输入框和标签优先 `6px–8px`。
- 卡片与抽屉内部区块：`8px–12px`。
- 弹窗与大容器：`12px–16px`。
- 默认使用 `1px` 细边框 `--border`；避免高对比粗边框和紫色光晕。
- 卡片默认 `--shadow-xs`，悬浮提升到 `--shadow-sm` 或 `--shadow-md`。
- 信息层级依靠背景、间距、字重和阴影区分，不使用大量分割线。

### 2.3 排版

默认字体为系统无衬线字体，正文基准 `14px`，行高 `1.5–1.7`。

| 层级 | 建议字号 | 字重 | 使用场景 |
| --- | ---: | ---: | --- |
| 页面标题 | 20–24px | 600 | 页面主标题，单页最多一个 |
| 区块标题 | 15–16px | 600 | 卡片、抽屉区块 |
| 正文 | 13–14px | 400 | 描述、表格内容 |
| 辅助 | 11–12px | 400/500 | 时间、来源、帮助文本 |
| 数据强调 | 20–28px | 600 | KPI 数值，避免过度放大 |

同一页面最多使用 4 个字号层级。标题与正文之间至少 `4px–8px` 间距，区块之间至少 `16px–24px` 留白。

## 3. 页面布局规范

### 3.1 统一页面骨架

页面采用：

```text
页面标题与说明
→ 关键操作区
→ KPI/状态摘要（必要时）
→ 筛选、搜索与视图控制
→ 单一主内容面板
→ 按需打开的抽屉/弹窗
```

- 默认单一主面板，避免固定三栏布局。
- 左侧选择、节点库和上下文操作移动到顶部或画布内的可收起面板。
- 详情、配置、审计和审批采用右侧抽屉按需打开。
- 顶部操作按“主要行动 → 次要行动 → 低频操作”排序；低频操作使用菜单或更多入口。
- 页面内容区允许滚动，顶部导航和抽屉 Header/Footer 保持稳定。

### 3.2 间距与呼吸感

使用 4 的倍数作为间距基线：`4 / 8 / 12 / 16 / 20 / 24 / 32px`。卡片内部建议 `16px–20px`，表格单元格建议 `12px–16px`，避免内容贴边或大面积空洞。

### 3.3 响应式

- `>=1280px`：主内容最大宽度约 `1440px`，信息区可横向排列。
- `768–1279px`：控制区换行，卡片调整为两列。
- `<768px`：单列布局；抽屉转为全屏或底部面板；表格提供横向滚动。
- 操作按钮不得仅依赖 hover；触屏设备必须具备可见的点击目标和状态反馈。

## 4. 交互与反馈体系

### 4.1 按钮状态

所有可点击元素必须有以下状态：

- 默认：清晰的边界与语义。
- Hover：背景加深、阴影提升或轻微上移 `1px`。
- Active：回到原位，避免持续跳动。
- Focus：品牌色 `2px` 焦点环，保证键盘可见。
- Disabled：降低透明度、禁止点击并保留原因（tooltip 或辅助文案）。
- Loading：按钮保留原宽度，显示旋转指示器并禁止重复提交。

主按钮只保留一个；危险按钮必须使用明确动词，如“删除节点”“清空画布”。

### 4.2 异步反馈

- 预计小于 300ms：按钮 loading 即可。
- 300ms–2s：按钮 loading + 状态文案。
- 超过 2s：显示进度、骨架屏或处理中提示，不得让页面假死。
- 成功、失败、警告通过 Toast 或行内反馈呈现；Toast 不承载必须阅读的长说明。
- 网络错误必须提供“重试”，并保留用户已输入内容。

### 4.3 动效

- 页面和抽屉过渡使用 `200–300ms`，缓动为 ease-out/ease-in-out。
- 动效只用于空间关系、状态变化和反馈，不使用循环装饰动画。
- 尊重 `prefers-reduced-motion`，减少位移和透明度动画。

## 5. 弹窗与抽屉

### 5.1 通用规范

- 遮罩：半透明黑色，必要时轻微 blur，突出当前任务。
- 关闭：遮罩、ESC、右上角关闭按钮三种方式均可用。
- Header 固定，包含标题、必要的上下文说明和关闭按钮。
- Body 独立滚动，Footer 固定操作区。
- 破坏性操作必须二次确认，并明确影响范围和可恢复性。

### 5.2 右侧抽屉

- 标准宽度：简单详情 `480px`，复杂配置或 AI 生成预览 `640px`。
- 桌面端从右侧平滑滑入；移动端自动全屏覆盖。
- 抽屉内使用分组区块，不再嵌套固定三栏。
- Footer 操作顺序：取消/关闭 → 次要操作 → 主要提交。
- 关闭时若存在未保存输入，应提示保存、放弃或继续编辑。

### 5.3 AI 生成工作流抽屉

流程固定为：

```text
自然语言输入 → 约束配置 → 生成中 → 草稿预览 → 校验/风险复核 → 创建隔离草稿
```

生成结果不得自动执行、发布、覆盖当前画布或授予权限。预览至少展示节点数、连线数、依赖、结构校验、风险扫描、质量评分和人工复核提示。

- 输入采用业务目标、风险等级与经工作区允许的模型；审计留痕由策略强制，不作为用户可关闭的选项。
- 高风险外部动作必须在生成图中补齐风险策略、人工审批、补偿回滚和审计留痕；缺少依赖或权限时，只能创建隔离草稿，不得试运行或发布。
- 应用生成结果必须创建新的 `revisionId`；当前画布有未保存修改时，默认另存为新草稿，不能静默覆盖。
- 生成记录应呈现模型、策略版本、提示词摘要、生成时间、到期时间和修订版本；提示词正文按数据分级与权限规则展示。

### 5.4 工作流画布与节点库

工作流页面采用“公共页头 → 一级视图导航 → 画布专属工具条 → 单一画布”的层级。版本、节点库和运行控制均属于画布视图，不出现在模板库或执行历史中。

```text
工作流标题与当前状态
→ 画布 / 模板库 / 执行历史
→ 当前版本 → 节点库 → AI 生成 | 保存草稿 → 运行试验 → 更多
→ 画布与按需出现的节点配置抽屉
```

工具条规则：

- `当前版本`是画布上下文胶囊，显示草稿版本并打开版本管理抽屉；版本切换、差异、发布、回滚均在此入口完成。
- `节点库`与`AI 生成`属于构建动作，放在版本之后；`保存草稿`是唯一实体品牌主按钮；`运行试验`为次级按钮，画布未保存、依赖待复核或策略未通过时必须禁用并说明原因。
- `更多`只容纳导出、重置、清空等低频动作；清空、回滚等破坏性动作仍需二次确认。
- 画布内仅保留一个可收起的节点库浮层和按需右侧配置抽屉，不设置永久三栏。

节点库不是通用组件市场，而是数字员工处置闭环的编排入口。默认提供“推荐下一步”和“全部节点”两种视图：

| 当前节点阶段 | 优先推荐能力 |
| --- | --- |
| 起点或触发 | Webhook、定时调度、告警事件、知识检索、Agent 决策 |
| 上下文与数据 | 数据转换、知识检索、条件判断、风险策略 |
| 智能决策 | 风险策略、人工审批、Skill、HTTP/MCP、创建任务 |
| 执行与协同 | 审计留痕、重试、补偿回滚、结果通知 |
| 治理与可靠性 | 受控执行、审计留痕、通知、人工任务 |

节点卡片必须展示图标、名称、简短说明和风险标签；高风险节点应标明“外部调用”“受控工具”“需审批”或“回滚”。支持点击添加和拖拽到画布；拖拽用于精确定位，点击用于快速搭建。首批标准节点按以下能力域组织：

- 触发与输入：Webhook、定时调度、告警事件。
- 上下文与数据：知识检索、数据转换。
- 智能决策：Agent 决策、条件判断、条件分支、并行编排。
- 执行与协同：Skill 执行、HTTP/API、MCP 工具、创建任务。
- 人工与治理：风险策略、人工审批、审计留痕。
- 可靠性与收尾：重试策略、补偿回滚、结果通知。

节点定义应统一维护类型、输入输出、配置 Schema、权限、风险等级、审计事件和失败策略。节点库、画布连线校验、配置抽屉、试运行门禁和审计记录必须复用同一份定义。

### 5.5 工作流治理与版本一致性

```text
生成记录 → 人工复核 → 隔离草稿 revision → 保存 → 校验 → 试运行 → 发布
```

- 每一份 AI 生成记录需具备 `generated / review_required / applied / discarded / expired` 生命周期；已应用或已丢弃结果只能只读查看，不能重复应用。
- 保存、校验、试运行和发布必须引用同一 `revisionId`。禁止出现“画布显示新流程，但服务端校验或执行旧流程”的版本错配。
- 对存在外部写入、HTTP、MCP 或 Skill 调用的流程，依赖、凭据权限、风险策略、审批、审计和补偿回滚均为服务端门禁；`review` 不能等同于校验通过。
- 生成、应用、放弃、保存、校验、试运行、发布与回滚均应写入审计；审计或草稿持久化失败时，不得显示“已应用”或继续进入可运行状态。
- 真实服务需从认证上下文推导租户、工作区和操作者，并执行 RBAC/ABAC。前端权限提示不能替代服务端授权。
- 真实服务还应实施提示词脱敏、密钥/PII 检测、模型白名单、区域路由、加密存储与保留期；Mock 中的提示词检查、所有者和到期状态仅用于验证交互契约。

### 5.6 工作流模板资产库

模板库用于发现和复用已验证的数字员工处置资产，不得呈现为无治理的示例卡片集合。

- 模板卡片至少展示名称、版本、维护团队、最近验证时间、风险等级、依赖健康度与成功率；安装次数和评分只可作为辅助信息。
- 提供分类、关键词、依赖/健康度筛选与空状态；模板详情展示真实 DAG、变量映射、依赖、权限、风险、最近运行表现和变更记录。
- “使用模板”与详情预览中的同名动作必须调用同一创建草稿流程：当前画布存在修改时创建隔离草稿，不得静默覆盖。
- 模板创建的草稿应保留来源模板 ID、版本和维护信息；后续保存、校验、试运行和发布纳入现有 revision 与审计链。
- 依赖未授权或风险待复核的模板可创建隔离草稿用于配置，但必须显著展示阻断项，并禁止试运行和发布。

## 6. 表单、列表与数据展示

### 6.1 表单

- Label、控件、帮助文本垂直排列，Label 使用 `12–13px`。
- 输入框高度建议 `36–40px`，Textarea 行高 `1.5–1.7`。
- Focus 使用品牌色边框与浅色 focus ring，禁止默认浏览器紫色/黑色 outline 覆盖设计。
- 错误信息显示在字段下方，使用红色文字和错误原因；不要只标红边框。
- 选择项较多时提供搜索；高风险选项显示风险说明和审批要求。

### 6.2 列表与表格

- 表格使用白色表面、细边框、充足单元格留白和行 hover。
- 不使用整行高饱和色边线；风险通过状态 Badge、图标和文字表达。
- 列表顶部统一放置搜索、范围、状态和主要操作。
- 多条数据必须支持分页或加载更多，并显示当前范围。
- 行点击打开详情抽屉，行内按钮只保留高频动作。

### 6.3 卡片与 KPI

- KPI 只保留可指导操作的核心指标，避免无业务价值的“装饰性数字”。
- 数值、标签、趋势和状态按固定顺序排列；数值不超过 `28px`。
- 卡片默认白底、12px 圆角、细边框和轻阴影；悬浮只提升阴影与边框对比度。
- KPI 不使用紫色光晕或多色渐变；状态异常使用橙/红语义色。

### 6.4 空状态、加载与错误

- 空状态说明“没有什么、为什么、下一步做什么”，提供一个主行动。
- 列表加载使用骨架屏或明确的加载状态，不显示空白页面。
- 错误状态展示原因、影响和重试按钮；抽屉详情失败不得静默隐藏。

## 7. 企业数字员工模块交互边界

| 模块 | 主任务 | 详情交互 |
| --- | --- | --- |
| 会话 | 对话、研判、受控行动 | 消息级工作卡、审批卡、上下文抽屉 |
| 任务 | 任务生命周期跟踪与处置 | 任务详情、审批、接管、审计抽屉 |
| 智能体 | 资产、市场、评测、治理 | 智能体详情与配置抽屉 |
| 工作流 | 流程设计、节点编排、试运行 | 节点属性、调试、AI 生成抽屉 |
| 知识 | 知识库与文档检索 | 文档详情、引用溯源抽屉 |
| 技能 | 技能资产与执行能力 | 技能详情、依赖和调用记录抽屉 |
| 模型 | 模型、路由、评测与调用审计 | 模型配置和审计详情抽屉 |
| 渠道 | 消息渠道连接与投递治理 | 渠道配置、健康状态抽屉 |

模块不得互相重复承载发布、审批、审计和监控职责；跨模块动作通过链接或上下文抽屉跳转。

## 8. 可访问性与质量门禁

- 所有图标按钮提供 `title` 或 `aria-label`。
- 键盘可完成导航、打开、关闭和提交；ESC 关闭当前最上层弹层。
- 文本与背景满足 WCAG AA 对比度要求；状态不能只靠颜色区分。
- 交互组件必须验证默认、Hover、Active、Focus、Disabled、Loading、Error、Empty 八种状态。
- 提交前至少执行：`pnpm --filter web typecheck`、`pnpm --filter web build`、`git diff --check`。

## 9. 实现映射

- 设计 Token：`web/src/styles/global.css`
- 通用 Button、Card、Input、Textarea、Badge：`packages/ui/src/index.tsx`
- 通用 Drawer、Modal、ConfirmDialog：`web/src/components/shared/`
- 页面级交互：`web/src/pages/`
- Mock API 与异步状态：`packages/api/src/mock.ts`、`web/src/services/query.ts`

本规范是页面评审和开发验收的共同基线。新增组件必须复用现有 Token 和交互模式，确有例外时需在组件文档中说明原因。
